Profile & Settings
Actions for You

A smart recommendation area within the Bank Profile & Settings experience that surfaces the most relevant actions for each customer — from security setup to privacy reviews. I led the UX research and strategy to define how recommendations should be prioritized, displayed, and managed.

My role

What I was responsible for

Role type
UX Research & Strategy
Methods used
Experience review, workflow analysis, scenario analysis, stakeholder discussions
Deliverables
5 findings, 5 recommendations, priority framework, decision matrix, lifecycle rules, user flows, UI screens
The problem

Too many actions, no clear priority

Users could have many eligible actions simultaneously. Without a prioritization system the recommendation area risked becoming cluttered and overwhelming — the opposite of helpful.

No prioritization logic

Security-critical actions appeared alongside optional preferences with no visual difference in importance.

No lifecycle rules

No defined rules for when actions should appear, disappear, or reappear after a user completes or dismisses them.

No user-type logic

New users need onboarding actions. Existing users need maintenance actions. The system treated all users the same.

Cognitive overload risk

Without a cap on displayed recommendations, too many actions at once reduced users' ability to act on any of them.

Research approach

UX strategy and experience definition

Existing experience review

Analyzed current Profile & Settings structure and how the recommendation area currently behaves.

Workflow analysis

Examined how recommendations appear, disappear, and reappear based on different user actions.

Scenario-based analysis

Built scenarios across new users, existing users, highly engaged users, empty states, and edge cases.

Stakeholder discussions

Worked with product and UX stakeholders to understand business goals and expected customer journeys.

Key findings

Five things the research revealed

1

Too many actions at once causes clutter

Users can have many eligible actions simultaneously. Without prioritization, the recommendation area becomes overwhelming and users cannot identify what to act on first.

2

Not all actions are equal

Security and required actions carry significantly more importance than optional preferences. The design needs to reflect this hierarchy so users always prioritize the right things.

3

Different users need different recommendations

A new user needs onboarding actions. An existing user needs maintenance and compliance actions. One-size-fits-all recommendations do not serve either group well.

4

Lifecycle rules were undefined

No rules for when actions appear, when they disappear after completion, when they reappear, and what replaces a completed action — creating inconsistent and unpredictable behavior.

5

Ranking needs to be transparent and consistent

Users should always see the most relevant and important actions first. Ranking logic must be consistent across all user types and predictable so users build trust in the system.

Priority framework

10 priority rules that govern all recommendations

These rules determine which of the many eligible actions appear, in what order, and what happens after a user completes or ignores them. They became the foundation for the recommendation engine logic.

RulePriorityLogic
1HighSecurity actions have the highest priority
2HighRequired profile completion actions rank above optional actions
3MediumPrivacy, consent, and compliance actions rank next
4MediumDigital adoption actions rank after profile and security actions
5LowPersonalization actions have the lowest priority
6N/AIf multiple actions share the same priority, the oldest incomplete action ranks higher
7N/ACompleted actions are removed immediately from the list
8N/AThe next highest-ranked eligible action replaces a completed recommendation
9N/AIf fewer than 3 eligible actions exist, only available actions are displayed
10N/AIf no eligible actions remain, display the empty state experience
System behavior

How the system responds to every user action

Completion state
Criteria 01
When a user completes a priority activity, it is removed from the eligible activity list
Criteria 02
System re-evaluates all remaining activities against eligibility criteria
Criteria 03
Completed activity is no longer considered during priority assignment and ranking
Replacement state
Criteria 01
After completion, system automatically identifies the next highest-ranked eligible activity
Criteria 02
Ranking process is re-executed to ensure Top 3 always reflects highest-priority pending actions
Criteria 03
Newly ranked activity replaces the completed activity in the Top 3 list immediately
Empty state
Criteria 01
All priority activities have been completed by the user
Criteria 02
No activities are applicable to the user's current account type
Criteria 03
All available activities are restricted by current business rules
Design recommendations

Five recommendations that shaped the product

Rec 1

Priority Framework

Three priority tiers — High (security setup, required profile completion), Medium (privacy and compliance), Low (optional personalization) — ensure the most critical actions always surface first.

Rec 2

Recommendation Decision Matrix

Defined customer action, eligibility rules, appearance, disappearance, and reappearance criteria for every action type. This became the foundation for the recommendation engine logic.

Customer action triggerEligibility rulesAppearance criteriaDisappearance criteriaReappearance criteria
Rec 3

Top 3 Recommendation Model

Display only the three highest-priority eligible actions at any one time. Directly prevents cognitive overload while ensuring the most important actions always have visibility and space to act.

Rec 4

Lifecycle & Refresh Rules

Established clear rules for completion, replacement, refresh, and empty state — ensuring consistent recommendation behavior regardless of what action a user takes.

Action completionReplacement logicRefresh triggersEmpty-state handling
Rec 5

Customer Scenario Framework

Validated recommendation logic against five user types — new users, existing users, highly engaged users, empty states, and edge cases — to ensure consistency across every customer scenario.
